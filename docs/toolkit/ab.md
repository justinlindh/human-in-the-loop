A/B any command against main: it runs `<cmd>` in a temporary worktree of the base (the merge base with `origin/main`, or `--base <ref>`) and in this checkout (uncommitted edits included) at the same time, both under `nice`, then prints one diff, in place of building a main worktree by hand and diffing the outputs. `ab.sh -- node scripts/balance.js --seeds 300`, or `ab.sh --id key -- bash -c 'node blender/checks/sweep.mjs --out $d; cat $d/report.json'`. The base result is cached per (base commit, command, `--key`, directory) under `~/.cache/hitl-ab/<sha>/` (`HITL_AB_DIR` changes it), so the next run on the same main commit, by any lane, only runs this tree; a second run computing the same base waits for the first. `--key <text>` separates runs that differ by something the command line doesn't show (an env var, an input file); `--refresh` recomputes the base, `--no-cache` skips the cache both ways, and a failed base run is never cached. When both outputs are JSON the diff lists each changed path with the old and new value, the delta and the percentage (arrays of objects match by `--id <field>`, else by index; `--tol x` ignores numeric changes up to x; `--ignore <regex>` drops paths such as timings; `--max` caps the lines and `--json <file>` writes them all); otherwise it is a unified text diff. Exit 0 whatever the diff (`--fail-on-diff` makes a difference exit 1), 3 when the command fails on either side (its stderr is shown), 2 for bad arguments. A tree with no changes against the base says so and runs nothing (`--force` runs anyway). For bot-seed comparisons that need per-seed pairing, use [pair](pair.md); `ab.sh` is for everything else. The worktree and the command's process group are removed on every way out ([worktree](worktree.md)).
