Runs before each Bash command: blocks `pkill -f` and `pgrep -f` (stop processes by PID), `git stash` other than `list` and `show` (all worktrees share one stash stack: commit to a scratch branch or copy to your scratchpad), any push to `main` or forced push, running `scripts/ci-pr.sh <pr>` by hand (auto CI is the one path; `--allow-bot` and `HITL_MANUAL_CI=1` get through), and `gh pr create/comment/review/edit` text or body files that contain a local path.

It also refuses a test run piped into `grep`, `tail` or `head` when it is the last test run before a `git commit` or `git push` in the same command: the commit would then ride on the pipe's last command, not the tests. Gate on the exit code (`npm run test:fast >/dev/null 2>&1 && git commit ...`), or use `set -o pipefail` or `PIPESTATUS`.

It also refuses a foreground loop (`for`, `while` or `until`) whose body both sleeps and checks PR or CI state (`gh pr`, `gh run`, `gh api`, `pr-status`): run `scripts/wait-for.sh <pr>` in the background instead. A single look, a background command, and loops that only wait on local files get through.

It also refuses `scripts/wait-for.sh` run with a trailing `&`, `nohup` or `setsid`: the shell-backgrounded watcher dies with the tool call. Run `scripts/wait-for.sh <pr> --merged` as its own call with `run_in_background: true` and `timeout: 7200000`; quoted text and heredoc bodies that only mention it get through.

It also refuses `sed -i` (and `--in-place`), `perl -i` and redirecting writes (`>`, `>>`, `>|`, `&>`, `tee`) whose target is a file tracked in the repository of the command's working directory, because lane-guard only sees the Edit and Write tools: change tracked files with those. The same goes for a `python`/`python3`/`node` one-liner (`-c`, `-e`) or heredoc that opens a tracked file for writing by a string-literal path, directly or through a variable assigned from one (`open(p, 'w')`, `Path(..).write_text`, `writeFileSync`): the refusal points at the Edit and Write tools. Not covered: `shutil.copy`, `os.replace`, `fs.renameSync` and `fs.copyFileSync` onto a tracked file. A script file run by name, a path built at run time (`sys.argv`, `os.path.join`), reads, and writes to scratch or untracked files get through. Writes to `/tmp`, a scratchpad, `/dev/null`, logs and any untracked file get through, as do quoted text and heredoc bodies that only mention a tracked path. A target that is a `$VAR` or `~` path is not resolved and gets through. To restore a tracked file from git use `git checkout`, not `git show > file`.

A reviewer's disposable checkout (a detached worktree whose directory is named `review-*`, as `scripts/review-prep.sh` makes) is exempt from those shell-write refusals, so a scripted sweep can edit a constant, run the check and repeat; lane-guard already lets Edit and Write through in a detached checkout. Nothing is committed from there: `git commit` run in it (from its directory, or with `git -C <it>`) is refused. A `cd <it> && git commit` is not looked through. The exemption is judged by where the write lands, not where the session sits: from a review checkout, a command that changes directory (`cd`, `pushd`) or aims git elsewhere (`git -C`), an absolute target outside the checkout and a target that climbs out of it (`..`) keep the refusal, and a tracked file in another worktree of the repository is found by its own path. A lane worktree, a detached checkout with another name and a branch checkout named `review-*` keep every refusal.
