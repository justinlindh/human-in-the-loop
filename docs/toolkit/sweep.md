The scene integrity sweep: walks every mock and bot-played seeded games (every few weeks, each stage and era, each staged decision while its moment plays) and tests all pairs with exact mesh intersection (three-mesh-bvh). Reports overlaps, floating props and furniture, held props away from the hand, anything outside the room, people inside furniture, walls or each other along real walks and poses, what someone holds or carries inside their own head or torso, models reaching past the sim's footprint tiles (every item, level and rotation, except onto the front row the sim keeps clear for an item with a front zone; desks' seats on the sim's chair tile), speech bubbles or stat labels covering each other, a face or an emote on screen for more than a few drawn frames, and tooltips off screen or covering what they explain; every moment (each captioned or staged decision, and each ambient prop moment) is played on purpose in the floor mock, so a new moment is checked even if no seeded game fires it, with the state, time, both things, the depth or gap, and a crop of each. New violations fail it, except that in fast mode ones seen only in the seeded game are advisory (any sim change replays it differently; `--full` or `--strict` fails on them). `blender/checks/sweep-baseline.json` lists accepted ones; A crop is taken of each new violation and of each accepted one that reads deeper than its accepted depth (so `scripts/baseline-media.sh` has a crop for a raised entry). `--update-baseline` adds what the run found and keeps the rest unless `--prune`. Each accepted entry names the issue tracking it (`"issue": n`, printed beside the violation); a fix PR removes its entries. Writes `report.json`, `report.md` and crops to `--out` (default `shots/sweep/`). Fast mode by default; `--full` for more seeds, longer windows and denser sampling. Each seed runs in its own browser with a time limit (`--seed-limit`, 300 s fast and 1200 s full); a seed past it is skipped and fails the run with the week it reached. Narrow a run with `--mocks a,b` and `--seeds 1,2`.

A pair whose vertices sit under the tolerance but whose surfaces cross is measured by the crossing curve too (a thin surface such as a desk top or whiteboard through a head has no vertex inside it): it counts when the curve spans at least half of the smaller mesh and the smaller mesh has points on both sides of the other, and its depth reads as half the curve's extent. A thing only sunk into a surface is not counted. `tests/tools/intersect-thin.test.js` plants a slab of 1, 3, 6, 12 and 25 cm through a head-sized sphere.

Saved states from a `find.js --where` scan, which the index doesn't hold so `--moments` can't name them: `--snapshots a.json.gz,b.json.gz` (each match's `snapshotFile` from `--json`) loads each one and plays it as a moment (16 s, plus 8 s after any decision), labelled `snap:<name>`; findings count as seed findings. With `--seeds none --mocks none` it checks only those states. The office robot is one of the bodies checked, against everything but its own dock.

The moments pass also plays dog and cat greetings on Medium quality to cover the reaching pose, then restores Low for the rest of the sweep.

The sweep runs the same samplers (`sample.js`) in Node on the studio engine (`scripts/studio/sweep-host.mjs`) by default; `--browser` runs them in a browser instead (the old path, and the way to get crops of the collision rows). The engine run needs no Vite server, browser or GPU for the collision rows, and a seed is played in the same process. The collision rows (overlap, person, self) read each mesh pair through the engine's `meshContact` and `depthAtTol` at the tolerance of the check (the same `pairDepths` rule, `useInterior` in `intersect.js`), on the same body lists, own-desk skips and baseline as a browser run. The checks that read the page (screen, tooltip) are browser-only: once the engine work is done the run starts a small browser step of its own (`--screen-only`, the office window and tooltips of each mock, seconds, under the render lock) and adds its rows to the report; `--no-screen` skips it. Screen checks in moments and seeded games are made only under `--browser`, which `--strict` implies (the main guard's run keeps every check); a gate that must make them (a `--moments` run) passes `--browser`. Rows from the engine have no crop (`--browser` gives them). Every mode runs on the engine: `--moments` and `--snapshots` load each saved state through the sim's own dispatch (the open decision answered with its choice), `--replay` replays a report's states (indexed moments too), and `--against` runs the control on the other checkout on the engine as well (this checkout's engine on that checkout's game code). A seed has no time limit (`--seed-limit` applies to browser runs). `node scripts/studio/sweep-parity.mjs <browser report.json> <engine report.json>` says whether two runs found the same rows at the same depths (within 5 mm, in the same states); exit 1 when they do not. The two matched on the full seed set, apart from one phase-sensitive dance row.

Iterating on one item's violations (a NOC-style round): `sweep.mjs --item noc --seeds 1,2,4` checks only pairs that involve that item, takes its footprint pass in the floor mock, and opens a seeded window only in weeks the item stands; the game is still played week by week, so the windows it does open are the ones a full sweep opens. Once a full run has written `report.json`, `--replay <out>/report.json` re-checks only the states its violations came from (each seed's weeks, the mocks, indexed moments) and prints how many of the reported violations are still present and which are gone, so a fix is confirmed without another full sweep. `--states seed:1:w144,seed:2:w282` narrows the replay to the named states (with `--item`, one state per violation is enough to confirm a fix), and a replay with nothing to check exits 2. A report carries the mode it came from (`--full` or fast) and the replay plays in that mode; a report from a full run written before that field existed needs `--full` too. Windows the replay skips still step the world the same way a checked window does, so the states it does check are the ones the full run saw. A checkout given to `--against` by path counts with its uncommitted edits to tracked files, so a control patch works. `--against <root|ref>` runs the same scoped or replayed run on another checkout at the same time (a worktree path or a git ref such as `origin/main`; it runs this checkout's sweep files on that checkout's game code) and counts a violation as new only when that run lacks it, in place of a hand-run control sweep and diff. The three combine (`--item noc --replay report.json --against origin/main`). A replay of a seeded state assumes the sim is unchanged since the report: merge `main` and the played weeks shift, so run a fresh full sweep then. Run the full sweep once at the end, and `--update-baseline` from that. `--replay <report.json> --states <state>` replays one state on the studio engine in seconds (one seeded week about 10 s, a mock's moments pass about 30 s) with no browser or render slot; an indexed moment in the report replays from its snapshot in about 5 s.
