A cold `--scene` run plays on the studio engine (about a second, no browser) unless the request needs a page: `--browser`, `--snapshot`, `--moment`, `--render-reference`, a `faceCovered` rule or bubble cover (label layout), or a `--patch-js` that calls `window.__HITL` controls other than `state`. The first output line says which, and why.

`--scene --serve` answers every request in a page. It keeps the browser and Vite server open across requests instead of paying their startup cost (most of a cold command's time) every time: pipe one JSON object per line to stdin, the same fields as the flags above in camelCase (`mock`, `moment`, `snapshot`, `patchJs`, `event`, `warm`, `frames`, `clip`, `every`, `who`, `view`, `rig`, `expect` as an array, `slowRaycast`, `renderReference`, `profile`, `json`), and it prints the same table, verdicts and `--json` rows a cold run of that request would, then a `POSE serve <n> code=<0|1|2> ...` summary line; send the next request only after that line arrives. Send `{"quit": true}` when done rather than relying on stdin EOF or closing the caller: it ends the session at once and frees the GPU render slot; a caller left open without it holds that slot until killed. Each request opens a fresh page rather than reusing one: a reused page's camera and character animation keep easing toward whatever the previous request left as their goal instead of starting fresh, so its rows do not match a cold run, and a fresh page's do. That still leaves per-request cost at page navigation plus model and font readiness, a few hundred ms rather than a cold command's 1.6 to 2.3 s. Getting closer to the sampling cost alone (roughly 300 ms) would need a render-side reset hook that puts a freshly-opened page's camera, character and clock state back to their start values on request, cutting page navigation and asset readiness out of the loop; nobody's asked for that yet.

Scene rules use all requested sample frames as their denominator. Every subject selected by `--who` or a rule prefix must have a sample at every requested frame; without `--who`, this applies to every discovered subject. Missing samples and an empty scene fail even without rules. A relaxed `@share` permits threshold misses, not missing samples. Both `--scene` and `--check-browser` reject a `--root` that differs from the tool's checkout. Run the tool from the checkout being measured.

`--seed N [--week W]` stages a real seeded game (the page's `?seed=N&weeks=W`, no mock): W weeks played with each open decision answered by its first choice. `--patch-js` may `await`, so a patch can import the sim and play weeks first (`const sim = await import('/src/sim/index.js')`, `window.__HITL.tickN(1)`, `window.__HITL.dispatch({...})`, then `R.sync(S)`, `window.__sample(n)` and `R.handleEvents(events, S)` for the renderer to react). Use `--warm 0` when the patch replays the sim from week 1: the warm-up frames run the game's own clock first. To find who does the gesture, run without `--who` and read `anim` (`facepalmsit`) in the rows, then rerun with `--who <id>` and a cover rule over the gesture's frames.
