**Pass rules.** A gesture's matrix passes when every judged cell holds its rule. Run `--matrix` with neither `--measure` nor `--expect` and it uses that gesture's own rule, printing it on the first line (`pose-matrix.js` `PRESETS`, which `scripts/studio/parity.mjs` uses too):

| Gesture | Rule | Measures shown |
|---|---|---|
| `facepalm` | `coverHandEyeNear>=0.5@0.7 if faceCam<=80`: a hand covers at least half the near eye in 70% of the frames where the face is within 80 degrees of the camera | `coverHandEyeNear`, `faceCam`, `hand0Eye`, `hand1Eye`, `clearance` |
| `slap` | `robotContact<=0.06@0.01` (the right hand within 0.06 m of the robot head at some frame) and `robotAngle<=35@0.8` (the face within 35 degrees of the head for 80% of frames), stage.mjs's `robot.slap` and `robot.windup` rules | `robotContact`, `robotDepth`, `robotAngle`, `faceVisible` |

Any other gesture needs `--measure` (and its own `--expect`).

**The matrix: `--gesture <name> --matrix views=all,postures=all,builds=all,rig=on,off [--measure <m1,m2,...>] [--expect '<rule>']... [--crop worst.png] [--json out.json] [--jobs N] [--browser] [--rows]`.** One Node command on the studio engine, no browser and no render slot, plays the gesture in every cell and judges each one: `views` 0 to 3 (the person's heading off the camera, 90 degrees a step), `postures` `stand` (over `idle`), `sit` (over `typing`, so the seated variant plays) and `lie`, `builds` 0 to 2, `rig` `on` and `off` (the authored clips against Low quality's procedural poses), and optionally `accessory=none,glasses,headphones,beanie,cap` (each axis defaults to all; a list runs until the next `name=`). Measures are the gesture measures above (`hand0Face`, `hand1EyeLeft`, `faceCam`, ...), any screen cover `cover<A><B>` (`coverHandEyeNear`, see `--scene`), and `clearance` (the smaller of either hand's distance to the head surface). A rule is `<measure><op><value>[@<share>] [if <measure><op><value>]`: the share of the gesture's frames that hold (default all), over the frames where the `if` holds (`coverHandEyeNear>=0.5@0.7 if faceCam<=80` leaves out frames with the face turned from the camera; a cell with none left is `n/a`, counted apart from passes and failures). It prints one grid per rule (rows posture, build and rig; columns the views; the share that hold, failing cells starred, the worst cell marked `<`), then `MATRIX <gesture>: p pass, f fail, k n/a (N cells)` and the worst cell with each measure's min..max over its gesture frames. The worst cell has the lowest share, ties broken by how far its best frame is from the bound. Exit 1 when a rule fails in any cell. The cells are spread over `--jobs N` processes (default a quarter of the cores; each plays every n-th cell, and the answers are the same for any N), so the full 72-cell facepalm matrix takes about 2.5 s and the 36-cell slap matrix under 1 s. `--browser` plays the whole matrix in one harness page instead (under the render lock), the reference the engine is held to; `--rows` prints one `CELL <ok|FAIL> <posture> b<build> rig-<on|off> <accessory> <cause> side<n> view<n> {...}` line per cell with its verdicts and ranges, and `node scripts/studio/parity.mjs --preset facepalm` (or `--preset slap`) runs both and compares every cell. `--crop worst.png` then draws one picture of the worst cell at its worst frame (the person alone on the floor, drawn by the game's renderer on the GPU under the render lock, cropped on the head; `pose-crop.mjs` takes the same cell by flags for any cell). `--json` writes every cell's verdicts and ranges.

`--matrix` composes with `--param` (one run with a value) and `--sweep NAME=a,b,c` (the whole matrix once per value, each in its own process since a param applies as modules load): `--sweep 'PALM_STAND[2]=0.2,0.27,0.35'` prints one line per value (`p pass f fail k n/a of N`, counted as the matrix counts them, then `judged J frames`, the frames its rules judged over every cell, and its worst cell, `ALL PASS`, or `no cell fails` when some cells are n/a) and ends `SWEEP passing every judged cell: ...` (the values that fail no cell), so "which value passes every cell" is one command. A rule's `if` decides which frames are judged, so a value can pass more cells only by turning the face past the filter while the hand gets no closer: any value that judges fewer frames than the most-judged value gets a `SWEEP warning:` line, which says so when it also passes more cells. Read the hand's measure ranges before trusting such a gain. A swept name the run can't resolve (not found, or declared in two files) is refused before anything runs, with the `--sweep 'file:NAME=...'` flag that works. A repeated `--sweep` multiplies into a grid (5 sweeps of 4 values is 1024 runs): the first line prints the run count, and a grid over `--max-runs` (default 64) is refused with exit 2. With `--sweep`, `--jobs N` runs N values at once (default a quarter of the cores), each value's matrix in one process. A grid ends with `SWEEP moves the pass count most: ...`, the swept params ranked by how far the mean passing-cell count moves across each one's values. A one-handed gesture plays the hand the game would at each view (`side=game`, the default: the left hand for views 0 to 2, the right for view 3, as the game's facepalm picks it); `side=1`, `side=-1` or `side=all` force a hand, and a single-gesture run takes `--side 1|-1` (default 1). The matrix runs the same `playPose` as a single gesture run, so its numbers agree with `--check-browser`.
