`npm run feature-media -- --check` renders nothing (under a second) and exits 1 when a PR leaves the feature inventory without its media: an `id:` in a `docs/features/*.md` entry whose bullet has neither a feature-media link (`Media: [clip](https://github.com/<owner>/<repo>/blob/feature-media/<name>.mp4?raw=true)`) nor `media: none (<reason>)` nor `media: pending (#<issue>)` (a game fix keeps it from reading on video); a media name that no manifest item (feature-media, era or capture, or an alias in `check.mjs`) can produce; a media name that is a feature-media item without `publish: true` (the refresh would never publish it, so the link would 404); and a feature-media or era item opened at an indexed moment that no longer resolves to a pre-tick snapshot (skipped with a note when the event index for this sim code is missing). `scripts/feature-media/coverage-baseline.json` lists the `<file>:<id>` pairs not yet covered, so only new gaps fail. A pair that gets covered can stay in the file: the check prints a note (`N baseline pairs are covered now`) instead of failing, so a batch that adds media does not edit the baseline and parallel batches do not conflict on it. `--write-baseline` rewrites the file without the stale pairs, as an occasional tidy-up of its own. `FEATURE_MEDIA_DOCS` and `FEATURE_MEDIA_BASELINE` point the check at other files.

Keeping published media current: a manifest item with `publish: true` puts its `.webp` and `.mp4` outputs on the `feature-media` branch (through `scripts/feature-media/publish.sh`) under the name `<item id>.<ext>`, or an out entry's `publishAs` (needed when an item has several outputs). `npm run feature-media -- --stale` prints, one per line and exiting 0, the publishing items that are stale: never published, or their spec, the render and capture scripts, or any file their last capture loaded (`items[id].requested` in capture's `index.json`) changed, from the per-item records of `blender/checks/cache.mjs` (`HITL_NO_CHECK_CACHE=1` makes every item stale). `npm run feature-media -- --only a,b --publish` renders those items on the GPU (taking the render slot itself), publishes each that rendered cleanly, and records its inputs only after its publish succeeded, so a failed or interrupted item stays stale; the record is cleared before the render. A failed item is named (`FAIL <id>`), the others still publish, and the exit status is 1. `--publish` needs `--only` and refuses an item without `publish: true`. An item with `audio: true` is recorded with the game's sound (capture's `--audio`, in a run of its own) and its non-looping `.mp4` outputs carry that sound as AAC; the render fails the item when the clip's integrated loudness is below the out entry's `minLufs` (default -40) or it has no audio stream.

Media from `scripts/feature-media/manifest.js` (rendered by `scripts/feature-media/render.mjs`): capture.js items recorded through the real game loop at 1920x1080, each with the files to make from it (`out`: a path, a size, an optional crop, a start and length for clips). Stills become WebP; clips become MP4 (plus WebM and a WebP poster), cut to length and blended end into start so they loop without a jump. Paths mirror the landing page's `img/` and `media/`, so `--out` can be a checkout of the site repo; `--compare` prints each file's size next to the same path in another folder.

The seed-2 `site-yak-backfire` setup stops expanding after eight staff on the Office Floor and waits for a real outage. Daily standups are disabled for the live shot so the team can react when the meme lands. Both trailer Yak beats use this item.

`site-loop-automation` uses seed 5 and rejects a search that cannot reach `agent_runaway_spend` in a live game. Its recording checks the active event, staged hot rack and visible bill card.

`site-loop-meeting` places a meeting table itself: bots never buy one (it is not in their decor list, `src/sim/bots.js`), so a real seed grown to the Office Floor gets one placed the way a player would (`suggestPlacement` then the normal `placeItem` action) before daily standups are forced on. `site-still-squads` plays a real game with the `squads` bot (`src/sim/bots.js`), which forms and posts squads on its own, so cohesion has time to build before the Squads tab is opened. The `moment-*` items (table `MOMENTS` in the manifest) are the feature inventory's staged moments: each loads an indexed snapshot from the week before the decision, follows the staged prop at a per-moment zoom (none: the wide view), holds the card about 5 s, then answers it by key. They write `moments/<name>.mp4`; publish them with `scripts/feature-media/publish.sh`. `site-loop-rotate` clicks the on-screen `.camrot-b` buttons (the same control a player uses) for a there-and-back turn, so the loop's two ends frame the same.

The Yak card clicks Share a meme during the outage, tracks the new chat ID and waits for its real replies. The displayed image must decode at its expected size and remain fully inside the delivery frame and scroll area. `timeout 360 nice -n 10 node scripts/feature-media/yak-check.mjs` exercises the real capture and rejects missing, undecoded, incorrect, hidden, clipped, undersized and text-only images, missing replies and a wrong post identity. A matching decoy cannot replace the clicked post.

`--sheet` writes `<out>/sheet.png` after the render: every still of the run in one grid, then one row of six evenly spaced frames per clip, each row titled with its file, and prints the path. It is `node scripts/tools/media-sheet.mjs <out.png> <file|dir>...` (see its entry), so the sheet can also be made for any folder of renders.
