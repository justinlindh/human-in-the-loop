The seeded event index: bots play seeds 1 to 20 (balanced, sensible, allHumans) in the pure sim in about 25 s, and every decision (with the choice made), era change, office move, incident, launch, company party (`party`, a company-wide celebrate; its id is the event's `cause` when it carries one, else `party`) and so on is indexed by seed, bot, week, era and stage, with a save-state snapshot just before staged decisions, era changes and office moves. `find.js` prints where an event happens and its snapshot. It exits 0 with matches, 1 with none (`--json` prints `[]`), and 2 when it can't answer; with `--json` a refusal prints `{ "error", "kind" }`, where kind is `stale-index` (indexes exist, none for this sim code), `no-index`, `build-failed`, `bad-index` or `no-query`, so a caller never mistakes a stale index for "no such moment". Tools stage straight to it: `scene.mjs` and `dump.mjs` take `--moment '<query>'` or `--snapshot <path>`, and `sweep.mjs` takes `--moments 'q1; q2'`. The index lives in `~/.cache/hitl-ci/events/`, keyed by a hash of the sim, data, save and build code; a tool asked for a moment builds it when the code has changed. Use it instead of playing and scanning seeds by hand.

**State queries.** `--where '<js>'` is a predicate over the event `e` (its type, id and own fields, plus seed, bot, week, era, stage, staff) and that week's state `s` (after the tick, read-only). Every week also raises a synthetic `week` event, so a pure state condition is `--where "e.type === 'week' && s.outage?.weeks === 0 && s.office.stage === 1"`. Index rows that satisfy a predicate which never reads `s` answer it. A predicate that reads `s`, or matches no index row, needs states the index does not hold, so find plays seeds and bots for it: `--scan-seeds 1-60` (the default) by `--scan-bots` (the index's bots, or `--bot`), `--scan-weeks` deep (1040), over worker threads at a lowered priority, handing out no more runs once `--limit` matches are in. `--no-scan` refuses to scan; a plain query scans only with `--scan`. Each match is a snapshot of the state just before the tick that raised it, in the game's save format (`snapshot` in the row, and `snapshotFile` with `--json`), loadable with `--snapshot <path>` or capture's `pre` items, so the game's own loop plays into the moment. `--setup '<js>'` runs statements on the state each week before the tick (`s` in scope) and `--turn-while '<js>'` limits the weeks the bot takes its turn; both change the game that is played, and the snapshot carries their effects. Results are cached under the sim hash by query, so a repeat is instant and a larger `--limit` resumes. A predicate that is not JS exits 2 (`bad-query`), and one that throws while playing exits 2 (`scan-failed`, with the seed, bot and week). Exit 0 with matches, 1 with none, as before. Use it instead of a throwaway script that plays seeds.

**Look-ahead, ranking and unreachable conditions.** `--then '<js over e, s, m>'` keeps each `--where` moment waiting up to `--within` weeks (52) for a later event or week where it returns truthy: `--where "e.type === 'week' && s.outage?.weeks === 0 && s.office.stage >= 1" --then "e.type === 'incidentResolved' && e.weeks >= 2 && e.weeks"` finds an outage that lasts at least two weeks, which is only known when it resolves. `m` carries the moment's fields, `m.e` its event and `m.s` a copy of its state. The snapshot is still from before the tick of the `--where` moment, and a non-boolean `--then` result is kept as `result`. `--rank '<js over m>'` orders matches by a number, highest first (`--rank m.result` for the longest outage), and plays every seed in range to do it. When a scan finds nothing it says why: which `&&` part of `--where` no played run ever made true ("so no bot game reaches it": a mock scene or a bot change is needed, not more seeds), or how many moments matched `--where` and none satisfied `--then`. `--json --explain` prints `{ matches, scan: { runs, clauses: [{ expr, runsTrue }], unreachable, whereMatchesWithoutThen } }` as one value; without `--explain`, `--json` stays the bare list.
