The scene dump: exact world position, facing, bounds and screen box of every person, item and staged prop, each person's animation, moment and beat, head, eyes, hands, feet, held prop, gaze hit and what they sit at or use, per frame, as `dump.json`. `--frames` is a comma list of whole frame numbers (anything else exits 2; `--clip <s> --every <n>` gives a range). With `--images` it also writes a clean and an annotated PNG (ids, boxes, facing arrows, gaze rays, the walk grid, paths, goals, and a cross where a path passes through furniture) per frame.

Without `--images`, `dump.json` is made on the studio engine (Node, nothing drawn, no browser or GPU): every field is the one the browser run writes, from the same page code. `--images` needs the browser (the PNGs are drawn), and `--browser` makes `dump.json` there without PNGs, to compare the two. Known difference: effect particles (an emote's sparkles) scatter from the game's random stream, so on a frame where one sits between the camera and a person, that person's `visible` share can differ slightly between the engine and the browser; an engine run is the same every time. Walking data too: the walk grid (blocked cells, walkable cells under furniture such as meeting chairs, and the obstacle rects behind each), the door, coffee, lounge and meeting spots and every item's front cells, and each person's path, goal, what sent them (moment, perk, goal key) and the first furniture their body passes through along the path. `node blender/checks/dump-query.mjs <dir> where|dist|rel|near ...` answers "where is X", "how far is A from B", "where is X's hand in Y's frame" per frame; `rel <person> <item>` also reports where the person stands against the item's real edge, per frame: the distance from their point (`.pos` by default; `.hand1`, `.feet` ... work) to the footprint of the item's bounds (0 and "inside the footprint" over it), the side in the item's own frame (front, back, left, right, "end" for a short face of an item at least 1.5 times longer than wide, "corner with ..." when two sides are both past), their yaw against the item's, and whether they face the nearest edge point (toward, across or away, with the angle off); the footprint is the floor extent of the dump's bounds, so an item turned off the grid reads as the square-on rectangle around it. `nav <x,z> [r]` says what each grid cell there is and why it's blocked; `path <id>` prints a person's whole walk and what it passes through. With `--views 0,1,2,3` the dump records, for every person and staged prop, how much of it each camera turn sees and what hides the rest; `dump-query <dir> visible <thing> [--views ...]` prints it with the best view (without `--views`, props get the current view only). With `--trace`, the dump records the moment ownership trace: who set each person's temp (the pose or errand overriding their goal), every start, end, interrupt, replacement and refusal with the function behind it, and the decision freeze; `dump-query <dir> trace [id]` prints it. Reach for it when a moment doesn't start or is cut short. Reach for `path` when someone walks through furniture or never arrives. The office robot is recorded too, as `robot` on each frame while it is in the office: its position, yaw, bounds and screen box, its job (`plan`: dock, rounds, home, party or broken, with the breakdown `cause`, the `stop` it heads to with that desk or person, and who is fixing it), its `goal` and its remaining `path`. `where`, `dist`, `rel` and `near` take `robot` (or `robot.center`) like a person, `path robot` prints its job, goal and way, and the annotated frame draws it in green. State positions from the dump, never from estimates off an image. Seeded games are played to the week by the balanced bot.

`--sweep-row <report.json> <state> [<person id>]` loads the exact scene a sweep violation row was sampled in: the report's seed replayed the way the sweep plays it (its mode's windows and steps, from `SEED_PLAY` in `sweep-plan.js`) and stopped as that window starts (a state like `seed:3:w556`, or a violation key whose states include one). It then dumps `--frames` from there like any scene (the violation's `t` is seconds into the window, so frame `t*30` is where it was seen), prints the report's rows in that window, and with a person id says whether they are in the scene (exit 1 when not). It runs on the studio engine; `--browser` plays the same window in a harness page instead, as a `sweep.mjs --browser` run plays its seeds (a low-quality seeded page at 1600x1000, the index's pacing pinned, the sweep's own sampler up to the window), then dumps `--frames` in that page, so one window can be compared across the two engines (`scene.engine` in `dump.json` says which; `--images` is refused). A browser run (`--browser`, `--images`, or `--sweep-row --browser`) whose page logged an error exits 1 naming the errors and writes no `dump.json` (it removes an old one in `--out`), since a page that broke part way would read as a real engine difference; `--page-errors-ok` writes it anyway and only warns. A browser replay plays every week before the window in the page, so a late window takes minutes: raise `--timeout` (default 600 s). A report from older sim code may name a window the current code never reaches (exit 1 says so). Code that changed since the report also moves people, so it warns first, in one line on stderr, when the report's `checkout` (the commit the sweep ran at, and whether it had uncommitted changes) differs from this checkout's, naming both commits, or when either had uncommitted changes; a report without one gets `report has no commit; can't check it was made from this checkout`. Rerun the sweep on this checkout before reading such a dump against the report's rows.

Each frame also contains `spotSearches`, a copy of `R.debug.spots[moment][search]`: candidate coordinates, first failed requirement or ranking rejection, score, selected index and coordinates, and whether an explicit fallback won. The dump prints a rejection-count summary for each retained search. Searches replace their previous record, keeping the latest attempt per search instead of a frame history; candidates after a first-fit success or a declared minimum score are not evaluated. This is separate from `spots`, the office's navigation landmarks.
