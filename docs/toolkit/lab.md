The pose lab: a dev-only page to tune a character gesture by eye and by number without a rebuild. `lab.mjs` starts Vite on this checkout with a live `--param` plugin and prints the page URL (`.../pose-lab.html`). The page loads one character in any animation (`under`) with any gesture over it, in any camera view (0 to 3), build (0 to 2), heading and rig setting (on is Medium and High, off is Low's procedural poses), with a timeline scrubber (play, step, drag), a skeleton overlay and a ray from each hand to the eyes (pink is hand 0, blue is hand 1), and live readouts: time, phase, face angle, hand-to-eye and hand-to-face distances, and the cover shares (`coverHandEyeNear`, `coverHandEyeL`, `coverHandEyeR`, `coverHandFace`). The numbers come from `blender/checks/pose-measure.js` (`createPoseRun`, the per-frame step `playPose` loops over) and `pose-cover.js` (`measureCovers`), the code `pose.mjs` and its matrix run use, so the page and the command line give the same value for the same frame. Scrubbing back replays the run from time zero (a fixed step makes that deterministic).

Constants: every numeric top-level `const` (a number or an array of numbers) in `src/render/character.js`, `robot.js` and `rig.js` gets a slider and a number box per element, with a filter. A change is sent to the server as `--param` specs and the page reloads on the new code (state, frame and the changed values survive in the tab's session storage). `copy diff` puts the changed constants on the clipboard as `-const`/`+const` lines, `copy --param` as `--param file:NAME[i]=v` flags for `pose.mjs`, and `reset` clears the overrides. `?gesture=facepalm&under=typing&view=1&frame=70` opens a given state.

A view turns the person (90 degrees a step, the camera stays on the game's first view), as `pose.mjs --matrix` does, so the lab's view n is the matrix's view n. The cover numbers are the run's own (`createPoseRun` with `covers`, the code the matrix calls), and the smoke test plants a hand on an eye and requires the covered eye to read at least 0.5 and the other under 0.1.

The matrix section runs `pose-matrix.js`'s `runMatrix` over `playPose` in the page, for the current gesture: an axes line (the `--matrix` syntax, default every view, posture, build and rig) and rules (one per line, the `--expect` syntax including `if faceCam<=80`) give a grid, one button per cell with the share of judged frames that hold, green or red, the worst cell outlined, and a summary line (`44 pass, 12 fail, 16 n/a (72 cells)`). A cell whose `if` leaves no frame to judge (the face is turned away) is grey `n/a`, not green: nothing was measured there. `pose.mjs --matrix` prints the same count and `n/a` in its grid. Clicking a cell loads that posture, build, rig and view in the viewport at the frame where its rule fails worst. `run on load` reruns the grid after each constant change (the page reloads on it), which is the tune loop: move a slider and watch the grid.

The layout stacks under 820 px wide and every control is at least 40 px, so it works on a laptop and by touch. The page is served by `lab.mjs` only (`pose-lab.html` is not in the build input, so `npm run build` emits nothing of it). `lab-smoke.mjs` opens the page in headless Chromium, checks that the lab's numbers for one frame equal `playPose`'s, that a `--param` override changes a measure, and that there are no page errors; `--out` saves a screenshot. It takes a render slot.

The robot slap: gesture `slap` (in the lab's gesture box, and `pose.mjs --gesture slap`, single or `--matrix`) plays two actors from `blender/checks/pose-slap.js`: the office robot built by `robot.js`'s own `buildRig`, and a fixer at the game's slap spot (the first `SLAP.radii` ring, turned to the robot with `SLAP.aside`, the robot turned an ear to them with its head tipped away and jolted when the hand lands, as robot.js poses it). The pair turns by the view under the fixed camera. Measures: `robotContact` (metres, the fixer's right hand to the robot head's box, the metric stage.mjs's `robot.slap` beat takes; the rule there is at most 0.06 m at some frame of the slap, so `--expect 'robotContact<=0.06@0.01'` over the frames from `SLAP_AT`), `robotDepth` (metres the fixer is inside the robot), `robotAngle` (degrees the fixer's face is off the robot head) and `faceVisible` (share of the fixer's face landmarks the camera sees). The slap constants are reachable as `--param src/render/robot.js:SLAP.aside=0.3` (`NAME.key=value` for the numbers of a flat object const), have sliders in the lab, and work with `--sweep SLAP.aside=0.05,0.12,0.2`. The fixer stands on the ring side-on to the camera, as the game picks its spot, and the robot's head tilt and jolt are robot.js's own `slapPose`. The stage's facing rule pins the fixer's turn: `--expect 'robotAngle<=35@0.8'` (the fixer's face within 35 degrees of the robot head) passes for `SLAP.aside` up to about 0.4 and fails from 0.6, and `robotDepth<=0.01` catches a fixer inside the robot; `--sweep SLAP.aside=0,0.12,0.25,0.4,0.6` shows the range. The hand lands within 0.02 m of the head box, the game's own run reads about 0.008 m, so the run agrees on pass and fail to a centimetre.

Not covered yet: accessories in the matrix axes, the robot stuck on a chair, and a fixer approaching from another side of the robot.
