The safe version of a context reset, for a teammate that just said "handoff ready". It holds with exit 3 and the reason on stdout when the teammate's team inbox has unread messages (someone is mid-conversation with it) or when one of its PRs has a failing `review` status (changes requested; the verdicts are posted as that status, the reviews themselves stay comments) on its head. A lane's PRs are on `<name>/...` branches, except the integrator's (`integ/...`), tools2's (`tools/...`) and team-lead's (`lead/...`). The gate fails closed: when `gh` can't answer it holds the lane (`held: couldn't read <name>'s PRs from GitHub`). Otherwise it compacts the teammate with `scripts/team/reset-teammate.sh <name> compact 60 --log <memory>/reset-trial.log` (see its entry: pane lookup, idle wait, the `compact_boundary` check, the log row) and then types a prompt asking the lane to re-read its handoff and restate its paths, open work and open threads, so the lead can check nothing dropped. `--check` stops after the gates and prints `gates pass for <name>; other handoffs naming it: ...`, which names the other lanes whose handoff mentions it, for the open-threads check. The team is the newest `session-*` directory whose `config.json` lists the name; none lists it: exit 1. Exit 0 compacted (or, with `--check`, the gates pass), 1 no team, no pane or the compact not confirmed, 2 bad arguments.

Where things live comes from the environment, not the script: the memory directory (handoffs in its `handoffs/` folder, the trial log in it) is `--memory`, else `HITL_MEMORY_DIR`, else `<config>/projects/<the main checkout's path with / and . as ->/memory` (`<config>` is `CLAUDE_CONFIG_DIR`, default `~/.claude`); the teams directory is `--teams`, else `HITL_TEAMS_DIR`, else `<config>/teams`. Needs `tmux`, `jq` and, for the changes-requested gate, `gh` run from the repository. `scripts/tools/hitl-lanes.test.sh` runs it against stand-in `tmux` and `gh`.
