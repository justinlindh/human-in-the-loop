Independent, experimental Node scene engine. Read [the design and frame contract](../proposals/scene-engine.md) before using its output. It runs the game's render update code with presentation adapters, local assets and an isolated worker. The engine path starts no Vite server, browser, GPU or render slot. Node must provide synchronous `registerHooks`.

Input is one of `--mock floor`, `--snapshot state.json.gz` (plain JSON also works), or `--seed 1 --week 112` using the balanced bot. Render time advances over a frozen input state from epoch zero. `--from` and `--to` use seconds on 1/30-second boundaries; `--every` is rounded to the nearest whole frame (0.25 becomes 8 frames, 0.2667 s, and a line on standard error says so). Each object carries `position`, its world position in metres (`x`, `y` up, `z`), beside the `world` matrix and `bounds`. `--rig` enables authored clips at Low quality. `--who s1,s3` selects subjects. `--facts intersections,clearances,visibility,projections,occupancy,walker` enables requested geometry facts; `walker` adds `facts.walkers`, one entry per person who is walking, from the renderer's `R.walkDebug`: their remaining `path` (waypoints `[x, z]`), `target` and `heading`, `speed`, the `drift` rule that fired this frame (`pass-right`, `step-apart`, `hold-back` or none, the other person, the step applied, or `refused`) and any `wait` (`stepIn` with its timer), so a replay shows why someone moved as well as where they were. Standard output is NDJSON, one record per line (`--json` is the same; `--json-array` prints one JSON array of the records instead); `--profile file.json` writes timings separately. Exit 2 indicates invalid input or an unavailable operation.

Each record includes semantic owners, part ids (the owner's id plus the mesh's path below the owner root, with sibling indices among same-named nodes, so an id does not move when other objects come and go; carried props are `held:<staff id>:<prop id>` wherever they hang; a single-mesh owner's part is `<id>/self`), transforms, conservative bounds, the real character joints, activity/target/held ids, the active camera, provenance and explicit capabilities. Check those capabilities before applying a rule. `depthM` on an intersection is the scene sweep's own metric (`pairDepths` of `blender/checks/intersect.js`, the helper `overlaps()` uses: the deepest sampled point of either mesh inside the other, and only when neither is deeper than 0.01 m, half the crossing extent for a thin surface through a body), measured on the posed geometry that decided the intersection (skinned and morphed meshes are baked; any other mesh is measured in its own space, as the sweep measures it, because the crossing reach depends on how the two meshes are turned), status `sweep-metric`, so studio and the sweep give the same answer on the same pair. The sweep's 0.01 m switch is a per-check tolerance (people use 0.02), so each intersection also carries `interiorM` and `crossM`, and `depthAtTol(contact, tol)` from `scripts/studio/geometry.mjs` gives the depth at the tolerance of the check a rule replaces (`depthM` is at 0.01). It is not a minimum separating translation, and a graze reads 0. Universal byte identity, per-instance export and multiple simultaneous views are not implemented. DOM bubble/label layout (screen rectangles) and cover remain browser checks.

A check's harness page function runs on the engine through `scripts/studio/page-host.mjs`: `runCases([{ page: { mock | seed, quality, rig }, module, fn, arg }], { jobs })` plays each case in its own process on a fresh scene with the globals a harness page has (`__hitlRender`, `__HITL`, `__tick(ms)`, `__advance`, `__step`, `__sample`, `__settle`, `__reseedGame`, `__tool`, imports by site path such as `/src/render/checks.js`), and returns `{ value }` or `{ error }` per case in order. The engine's DOM is a small working tree (children, classes, text, `isConnected`, and `querySelector` over class, tag and id selectors with descendant combinators, under `document.body` with the label layer), so a check that finds a bubble by class finds the game's label; nothing is laid out, so screen rectangles stay zero.

For parallel states, `node scripts/studio/batch.mjs --input requests.json --jobs 2` takes an array of library requests and emits frames in input order. Example: `[{"mock":"floor","frame":60,"facts":["occupancy"]},{"seed":1,"week":112,"frame":60}]`. The library exports `openScene` and `sampleMany` from `scripts/studio/index.mjs`; library sample times are integer frames. Always close a scene in `finally`.

`controls.mjs --out controls.json` checks planted geometry cases. `verify.mjs` checks observer independence, worker isolation and API failures. `compare.mjs --mock floor --out parity.json` uses the existing browser harness with drawing disabled, records every field difference at tolerance 1e-5, and exits 1 on a mismatch. It takes the normal render lock. A snapshot path can replace `--mock`. `--control-perk-delay 3` is an explicitly modified in-memory diagnostic on both sides; it does not establish parity of unmodified production code. `--trace-random` captures call stacks for diagnosis and should not be used for timings.

`bench.mjs --runs 3 --frames 15 --out benchmark.json` compares native and browser queries, with separate setup, step, sample, round-trip and lock costs. Wrap long commands in `timeout` and `nice -n 10`. No existing gate or lane workflow switches to this prototype automatically; the role-brief changes are deferred to the migration described in the proposal.
