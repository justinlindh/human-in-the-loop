Makes the public build installable and playable fully offline. `vite build` runs the `pwa` plugin, which adds the manifest and icon tags to `index.html` and writes `manifest.webmanifest` (standalone, scoped to the build's base), `sw.js` (the service worker, with this build's id) and `pwa-assets.json` (every file of the build with its size, plus the build's version and id). The dev server serves no worker.

**A normal browser visit loads exactly as before.** The worker registers but steps aside (no request is intercepted, no list is fetched) until a whole build has been downloaded into an offline set. The download starts only when the game runs as an installed app (`display-mode: standalone`, or `navigator.standalone` on iOS) or when the player taps "Download" in Settings (Offline). It skips everything when the browser asks to save data, unless the player asked.

**The offline set**: `src/dev/pwa.js` fetches every file in `pwa-assets.json` (one sound format per browser: Ogg Opus where the browser plays it, else m4a; about 48 MB on Chrome) four at a time into a cache named for the build (`hitl-set-<id>`), retries a failed file three times, skips files an earlier try already stored, and writes a completion marker last. A cut-off download pauses ("Download paused") and resumes on the next launch or when the connection returns; a set without its marker is never served. A small pill shows "Downloading for offline: 34% of 48 MB", then "Ready to play offline". `window.__HITL_OFFLINE` has the state (`state.state`: off, checking, downloading, paused, ready, error), `start()`, `peek()` (the size, for Settings) and `subscribe(fn)`.

**Serving**: with a complete set present, the worker serves from the newest complete set (pages ignore the query, so `?seed=` works), a range request (audio seeking) is answered from the cached whole file, and anything the set lacks goes to the network.

**Updates**: on every launch of an installed app (or of a browser that holds a set) the page fetches `pwa-assets.json`; offline, that fails silently and the game starts from the cached version. When the list's version differs from the running build's, the new set downloads in the background (its requests carry `X-Hitl-Download`, which makes the worker let them through to the network instead of answering from the old set); the running version and its set keep working. When the new set is complete it asks "A new version is ready. Restart to update?" with Restart now or Later; both builds' sets coexist until then, and the worker serves the newest complete one at the next page load. Restart reloads the page; the new build then asks the worker to delete the sets older than its own. An interrupted update resumes next launch and never half-applies. Saves live in `localStorage` and load on the new build through the sim's own migration.

`npm run pwa-check` builds two versions and drives a phone-sized Chrome (GPU slot) through: a plain visit makes no request beyond the worker and manifest and stores no set; Settings downloads on request with its size and progress; the installed app downloads with a progress pill, a cut-off download pauses and the next launch resumes, "Ready to play offline" shows, Chrome reports no installability errors; with the network off the game boots, a new game in the dotcom era plays its music files from the cache and runs weeks; a new release downloads while the old one runs, a cut-off update leaves the old version working, the prompt appears when complete, Restart now runs the new version, an old-version save loads, the old set is deleted; an offline launch after the update shows no prompt, pill or error. Screenshots go to `--out` (default `shots/pwa`). `scripts/pwa-plugin.test.sh` builds with two bases and checks the generated files and the sound-format filter (it runs in local CI).

`scripts/pwa-icons.sh` rebuilds `public/pwa/` (192, 512, maskable 512 and the iOS touch icon) from `docs/readme/logo-square.png`.

A new top-level folder under `public/` is part of the set automatically (the list is every file of the build).
