Keeps the site changelog (humanintheloopgame.com/changelog/) in step with the game, one day at a time. Days are UTC days, as the published changelog groups them: the default is yesterday in UTC, and a day's merges are those with a UTC merge time on it (`day-changes.mjs --tz UTC`), whatever the machine's zone. For the day it:

1. lists the player-visible PRs with `day-changes.mjs` and turns them into a plain-text digest (`changelog-digest.mjs`: titles, trimmed bodies, feature entries, still links, the `docs/effects` numbers). A day with none writes nothing;
2. runs `claude -p` on a cheap model (`CL_MODEL`, default `haiku`; read-only tools, a dollar cap) with the site's `CHANGELOG-VOICE.md`, the newest entries and the digest, and takes the one JSON entry it replies with. The model writes the text and lists each item's PRs (`refs`); it does not pick media;
3. puts the entry in the site's `changelog/entries.json` (`changelog-apply.mjs --media`): it checks the site's own rules (fields, the day, no em dash, no "startup"), then attaches each item's stills by rule (`changelog-media.mjs`), up to three per item, from the PRs it cites:
   - stills of features the PR adds first (their `docs/features` still links and art's `<kind>-<id>` still on the `feature-media` branch),
   - then the stills posted on the PR, in its body or comments (`pr-media.sh` posts there). These are ranked by file name: after, branch and desktop shots first; phone and tablet captures (a `<w>x<h>t` touch size, or a `<w>x<h>` size under 1200 wide such as `1180x820`; a desktop size such as `1920x1080` ranks level) lower; strips, sheets, pairs and `high-low` pairs lower still; before and main shots last,
   - taken in turn across the cited PRs so each one shows,
   - then, only to fill what's left, stills of features a PR only changed (an entry it touched in passing usually shows something else),
   - and, when no cited PR has a still, a frame from the middle of a PR's clip (ffmpeg, niced and under a timeout).

   Each still gets a caption the reviewer can check it against: the feature's name for a feature still, the link's own words for a posted still whose markdown label has them, else the PR's title past `type(scope): `. Stills are made webp no wider than 1280 px (the original is kept if ffmpeg can't) and land in `changelog/media/<day>/`, named `<pr>-<file>` (feature stills by their own name). Up to six candidates are fetched per item, and one much wider than tall (over 2.2:1, likely a strip or a row of frames) goes behind the rest. The run log names each item's candidates (`media: <title>: ...`).

   **The still check** (`changelog-still-check.mjs`) then makes the final cut. The rules read file names only, so a contact sheet or a stale capture with a plain name gets through them. The check is one `claude -p` run on `CL_CHECK_MODEL` (default sonnet; read-only tools, `--output-format json` for its cost) that opens every candidate next to its item's text and says what each one shows, camera first (eye level, overhead or interface), before it judges. On one day's candidates, haiku passed an overhead frame as first person and passed strips, and its verdicts changed from run to run, while sonnet's were right for about $0.30. The run's whole reply is kept in `<day>.check.raw`. It turns down a still that shows a different view or thing than the item says (an overhead frame for a first-person item), contact sheets, grids, strips, rows of frames, side-by-side comparisons and bare test captures. Each item keeps up to three stills that pass, in the rules' order, with a caption of at most 12 words written from what is visible. Kept items are never shown to it or changed. Its spending cap is what the draft left of `CL_BUDGET`, so a day costs at most `CL_BUDGET`. When it can't run (under $0.05 left, the run fails, the reply is no verdict, or `CL_STILL_CHECK=0`), the rules' first three stand and the log says why. The log and the PR body list each still it turned down with its reason, and an on-screen item it left with none joins **Stills wanted**. The day's media folder ends up holding only what the entry shows, so no spare file ships. A refused draft is retried once with the reasons in the prompt;
4. runs the site's `npm test`, commits, pushes `changelog/<day>` and opens the site PR (with auto-merge on), which the reviewer and the site's checks handle like any other. The site's branch protection requires `check`, `commits` and the reviewer's `review` status, so auto-merge waits for a verdict. The PR body asks the reviewer to check each number and claim against the game's code and `docs/effects` at that day's commit (the draft is model-written and has been wrong before), and each still against its item. An item about something on screen (any area but sound, economy, balance, performance, fixes and behind the scenes) that got no still is listed under **Stills wanted** in the PR body, for video to add one on the branch.

**Idempotent.** A day has one branch and one PR. The timer skips a day it finished, and a day that already has an entry in the site's `changelog/entries.json` on main, whoever wrote it, without calling the model. `--force` drafts the day afresh and replaces its entry: an open PR gets a new commit and a refreshed body, a merged day gets a new PR only when the text changed, and an identical redraft pushes nothing. `--dry` stops before the push and leaves the entry in the site clone.

**Published days keep what was curated.** `--force` on a day with an entry on the site's main keeps, unchanged and first, every published item the tool did not write, with its stills, and a published headline it did not write. The rest is redrafted. What it wrote is recorded per day after each push (`<day>.ours.json`, from `changelog-apply.mjs record`: the headline and each item's title and a fingerprint of its area, title, body and stills). An item whose fingerprint no longer matches was edited by hand since (new text, or a still video added), so it counts as curated and is kept. A record from before fingerprints matches on titles alone, and with no record everything published is kept. The drafter is shown the kept items and asked to cover only what they don't, and a drafted item with a kept item's title is left out (`changelog-apply.mjs keep` works out what stays, `--keep <file>` applies it). A kept item's media is never replaced: its stills are linked and never downloaded over or deleted, and a file nothing shows is removed. `scripts/tools/changelog-auto.test.sh` covers the skip, the kept item and stills with and without a record, an item edited by hand, the stills a PR's posts give, a clip frame, the Stills wanted list and the prompt; `tests/tools/changelog-apply.test.js` and `tests/tools/changelog-media.test.js` cover the rules underneath.

**Failure.** No usable draft, failing site tests, a failed push or clone: the run opens an issue labelled `changelog-red` in this repository (or comments on the open one) with the log tail, and opens no PR. A passing run closes it. Logs, the digest, the raw reply and the PR body are in `~/.cache/hitl-ci/changelog-auto/<day>.*`.

Env: `CL_STATE`, `CL_GAME_ORIGIN`, `CL_SITE_ORIGIN` and `CL_SITE_REPO`, `CL_MODEL`, `CL_BUDGET` (dollars per day for the draft and the still check together, default 2), `CL_CHECK_MODEL` (the still check's model, default sonnet), `CL_STILL_CHECK=0` (skip the still check), `CL_CLAUDE` and `GH` (stand-ins). Install with `scripts/systemd/install.sh` (the unit runs from the auto-CI worktree, and needs `claude`, `gh`, `node`, `jq`, `ffmpeg` and `ffprobe` on the user manager's PATH). A manual run for a past day: `scripts/tools/changelog-auto.sh 2026-10-03 --force`.

The voice and the entry format are video's (`CHANGELOG-VOICE.md` in the site repository); this tool only hands them to the drafter and applies what comes back.
