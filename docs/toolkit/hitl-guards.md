Shared guards for every lane's session, as function hooks that run inside Claude Code (issue #1313). A session loads the folder with `claude --plugin-dir <checkout>/scripts/tools/mods/hitl-guards`, or every session at once when its absolute path is in `CLAUDE_CODE_PLUGIN_DIRS` in the `env` block of the user's `~/.claude/settings.json`. Each guard fails open: if one errors, the call goes on as if the guard weren't there.

- **Shell rewrites of tracked files.** A Bash call that writes a tracked file from the shell (`sed -i`, `perl -i`, a `>` or `>>` redirect, `cat > f <<EOF`, `tee`, or Python or Node code that opens a path for writing) is refused before it runs. The refusal names each file, how it was written and its owner lane from `scripts/hooks/claude/lanes.txt` (the longest listed path wins, so `scripts/tools/` is tools' and `scripts/` integrator's). Change the file with Edit or Write, which lane-guard checks. Writes to untracked files (scratch output, logs outside the repo) pass. A write after `cd X &&` is resolved in X.
- **Branch switches under a watcher.** `git checkout <branch>`, `git checkout -b`, `git switch` (in the session's directory, after `cd X &&`, or with `git -C X`) is refused when the worktree has work armed on its current branch: a `scripts/wait-for.sh` whose working directory is in the worktree (it merges main into whatever branch is checked out), or a `job.sh` job of that worktree still running. Restoring files (`git checkout -- f`, `git checkout .`) passes, and a one-word checkout is a switch only when git reads the word as a commit. Use another worktree (`git worktree add <dir> <branch>`) or wait for the job to end.
- **Background job exits.** When a background Bash command's notification arrives, the row gains its exit code and the last 12 lines of its output. A check or test run (`blender/checks/`, `scripts/studio/`, vitest, `npm test`, balance, parity) that exits 0 without a result row in those lines (`CLIP`, `MATRIX`, `SWEEP`, `STAGEROW`, `CELL`, a `Tests N passed` line, a cache skip) gets a warning to read the log before taking it as a pass.

The command parsing is in `hooks/rules.ts` (pure, tested by `tests/tools/mods-hitl-guards.test.js`), and the hooks in `hooks/register.ts`. `hooks/register.test.ts` drives the hooks through `claude plugin test <folder>` against a fake host. `claude plugin validate <folder>` lists what the module hooks and calls.
