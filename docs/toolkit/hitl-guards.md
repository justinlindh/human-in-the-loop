Shared guards for every lane's session, as function hooks that run inside Claude Code (issue #1313). A session loads the folder with `claude --plugin-dir <checkout>/scripts/tools/mods/hitl-guards`, or every session at once when its absolute path is in `CLAUDE_CODE_PLUGIN_DIRS` in the `env` block of the user's `~/.claude/settings.json`. Each guard fails open: if one errors, the call goes on as if the guard weren't there.

- **Shell rewrites of tracked files.** A Bash call that writes a tracked file from the shell (`sed -i`, `perl -i`, a `>` or `>>` redirect, `cat > f <<EOF`, `tee`, or Python or Node code whose write call names the path: `writeFileSync`/`appendFileSync`/`createWriteStream`, `open(path, 'w'|'a'|'x')`, `Path(path).write_text`) is refused before it runs. Files the code only reads, and a path held in a variable, pass. The refusal names each file, how it was written and its owner lane from `scripts/hooks/claude/lanes.txt` (the longest listed path wins, so `scripts/tools/` is tools' and `scripts/` integrator's). Change the file with Edit or Write, which lane-guard checks. Writes to untracked files (scratch output, logs outside the repo) pass. A write after `cd X &&` is resolved in X.
- **Branch switches under a watcher.** `git checkout <branch>`, `git checkout -b`, `git switch` (in the session's directory, after `cd X &&`, or with `git -C X`) is refused when the worktree has work armed on its current branch: a `scripts/wait-for.sh` whose working directory is in the worktree (it merges main into whatever branch is checked out), or a `job.sh` job of that worktree still running. Restoring files (`git checkout -- f`, `git checkout .`) passes, and a one-word checkout is a switch only when git reads the word as a commit. Use another worktree (`git worktree add <dir> <branch>`) or wait for the job to end.
- **Session trailers.** In a `git commit` or `gh pr create`, `gh pr edit` or `gh pr comment` command, a line that is a `Claude-Session:` trailer or a bare claude.ai session URL is removed before the command runs, so the commit-msg hook doesn't refuse the commit after its gate. A session URL in the middle of a line stays, and so does a quote that closes the message on the trailer's line.
- **Background job exits.** When a background Bash command's notification arrives, the row gains its exit code and the last 12 lines of its output. A check or test run (`blender/checks/`, `scripts/studio/`, vitest, `npm test`, balance, parity) that exits 0 without a result row in those lines (`CLIP`, `MATRIX`, `SWEEP`, `STAGEROW`, `CELL`, a `Tests N passed` line, a cache skip) gets a warning to read the log before taking it as a pass.
- **Auto-merge after `gh pr create`.** When a non-draft `gh pr create` prints its PR URL, the mod reads the PR back (`gh pr view <url> --json isDraft,autoMergeRequest,labels`) and, when auto-merge is off, runs `gh pr merge <url> --auto --merge` with the URL the create printed (so a create run in another repo is read there) and tells the session. A `--draft` create, a PR that is a draft, or one labelled `awaiting-user` or `codex` is left alone, and so is one that already has auto-merge. It is the backstop for the repo's own open-PR hook missing.
- **Renders wait for the load.** A render or capture (`with-render-lock.sh`, `scripts/capture.js`, `npm run capture`, `scripts/reels/` tools, `scripts/feature-media/render.mjs`, `blender/checks/` golden, sweep, stage, clip, standup, pose, onscreen, scene and dump, `scripts/perf/bench`, `scripts/snap.js`, `npm run snap` and `gates`) is held while the 1-minute load average is 40 or more: it re-reads `/proc/loadavg` every 15 s for up to 10 minutes, runs when the load drops below 40 and says how long it held, and is refused with the load if it never did. A command that only mentions one (a commit message, a grep) is not held. An unreadable load runs the command. A `run_in_background` call is not held in the turn: the mod prefixes the command with a shell loop that waits on `/proc/loadavg` the same way, so the turn stays free.
- **Local paths in `gh pr` text.** In `gh pr create`, `edit` and `comment`, this checkout's absolute path and each worktree from `git worktree list` become repo-relative, in the `--body`/`-b` and `--title`/`-t` values only. A `cd`, a `--body-file`, other projects' paths and other home-directory paths are left as written.

The command parsing is in `hooks/rules.ts` (pure, tested by `tests/tools/mods-hitl-guards.test.js`), and the hooks in `hooks/register.ts` (their Bash chain is tested against a fake engine in `tests/tools/mods-hitl-guards-hooks.test.js`). `hooks/register.test.ts` drives the hooks through `claude plugin test <folder>` against a fake host. `claude plugin validate <folder>` lists what the module hooks and calls.
